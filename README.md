# Employee Management System API

A RESTful API for managing employees. Supports full CRUD operations, pagination, and a
consistent response envelope for both success and error cases.

## Technologies Used

- **Java 17:** The core programming language.
- **Spring Boot 3.4.5:** Framework for creating stand-alone, production-grade Spring-based applications.
- **Spring Data JPA:** For persisting data in SQL stores with the Java Persistence API, using Spring and Hibernate.
- **MySQL:** The relational database used to store employee data.
- **Flyway:** Manages schema migrations. Hibernate validates against it but never mutates the schema.
- **H2:** In-memory database used by the test suite.
- **Lombok:** A Java library that reduces boilerplate code.
- **Maven:** Dependency management and build tool.

## Prerequisites

- **Java 17** installed.
- **Maven** installed (or use the bundled `./mvnw` wrapper).
- **MySQL** database server running.

## How to Run

1. **Clone the repository:**

   ```bash
   git clone https://github.com/sunil-gumatimath/employee-management-curd-api.git
   ```

2. **Configure the database:**

   Connection settings are read from environment variables, so there is no need to edit
   `application.yml`. Every variable has a default, shown below.

   | Variable      | Default                              | Purpose                    |
   | ------------- | ------------------------------------ | -------------------------- |
   | `DB_HOST`     | `localhost`                          | MySQL host                 |
   | `DB_PORT`     | `3306`                               | MySQL port                 |
   | `DB_NAME`     | `employee-management-curd-api-db`    | Database name              |
   | `DB_USERNAME` | `root`                               | Database user              |
   | `DB_PASSWORD` | `root`                               | Database password          |
   | `SERVER_PORT` | `8080`                               | HTTP port                  |
   | `DDL_AUTO`    | `validate`                           | Hibernate schema mode      |
   | `SHOW_SQL`    | `false`                              | Log SQL statements         |
   | `FORMAT_SQL`  | `false`                              | Pretty-print SQL logs      |

   The database is created automatically if it does not exist. Flyway applies the
   migrations in `src/main/resources/db/migration` on startup, so the `employee` table
   needs no manual setup.

   > The default `DDL_AUTO` is `validate`, not `update`. Schema changes must be made by
   > adding a new Flyway migration rather than by letting Hibernate alter tables.

3. **Build the project:**

   ```bash
   ./mvnw clean install
   ```

4. **Run the application:**

   ```bash
   ./mvnw spring-boot:run
   ```

   The application starts on port 8080 by default.

## API Endpoints

The base URL for all endpoints is `http://localhost:8080`.

| Method   | Endpoint        | Description                                    |
| -------- | --------------- | ---------------------------------------------- |
| `POST`   | `/employees`    | Add a new employee                             |
| `GET`    | `/employees/{id}`  | Find an employee by ID                     |
| `GET`    | `/employees`    | List employees, paginated and sortable         |
| `PUT`    | `/employees/{id}`  | Update an employee by ID                     |
| `DELETE` | `/employees/{id}`  | Delete an employee by ID                     |

Employee IDs are UUID strings generated by the application.

### Query parameters for `GET /employees`

| Parameter | Default    | Notes                                                        |
| --------- | ---------- | ------------------------------------------------------------ |
| `page`    | `0`        | Zero-based page index                                         |
| `size`    | `20`       | Page size, capped at 100                                      |
| `sort`    | `empName`  | Sort field and direction, e.g. `sort=salary,desc`             |

## Response Format

Successful responses wrap the payload in a consistent envelope:

```json
{
  "status": 200,
  "message": "Employee with id = 8a3f... found",
  "data": {
    "empId": "8a3f...",
    "empName": "Ada Lovelace",
    "mail": "ada@example.com",
    "salary": 90000,
    "designation": "Principal Engineer"
  }
}
```

`POST` returns `201 Created`; `DELETE` returns `204 No Content` with no body.

Errors use the same `status` and `message` fields, so clients can parse both kinds with a
single contract. Field-level validation failures add an `errors` array:

```json
{
  "status": 400,
  "message": "Validation failed",
  "errors": [
    {
      "field": "mail",
      "rejectedValue": "not-an-email",
      "message": "mail must be a valid email address"
    }
  ]
}
```

### Status codes

| Status | Meaning                                                          |
| ------ | ---------------------------------------------------------------- |
| `200`  | Request succeeded                                                |
| `201`  | Employee created                                                 |
| `204`  | Employee deleted                                                 |
| `400`  | Validation failed, or malformed/unreadable request body          |
| `404`  | No employee with that id, or no such endpoint                    |
| `405`  | Method not supported for that endpoint                            |
| `409`  | Conflicts with existing data, e.g. a duplicate `mail`             |
| `415`  | Unsupported request content type                                  |
| `500`  | Unexpected server error                                          |

## Data model

An employee has the following fields:

| Field         | Type   | Rules                                                        |
| ------------- | ------ | ------------------------------------------------------------ |
| `empId`       | string | Generated UUID, read-only                                    |
| `empName`     | string | Required, max 120 characters                                 |
| `mail`        | string | Required, valid email, max 254 characters, must be unique    |
| `salary`      | int    | Required, must be greater than 0                            |
| `designation` | string | Required, max 120 characters                                 |

## Example Requests

Create an employee:

```bash
curl -X POST http://localhost:8080/employees \
  -H "Content-Type: application/json" \
  -d '{"empName":"Ada Lovelace","mail":"ada@example.com","salary":90000,"designation":"Principal Engineer"}'
```

List the first page, sorted by salary descending:

```bash
curl "http://localhost:8080/employees?page=0&size=20&sort=salary,desc"
```

## Tests
